# TSAnalyzeCutMerge

TsSplitter と rplsinfo を組み合わせ、TS/M2TS ファイルから**番組情報(放送局・番組名・放送日時)を読み取りながら自動的に分割**し、内容が分かるファイル名で保存するツールです。GUI(Tkinter)から操作できます。

D-VHS などでキャプチャした「パーシャルTS」で、1本のファイルに複数の番組・複数の放送局・日付をまたいだデータが混在しているケースを主な対象に、実機データ(`TEST-TSFile`)で検証しています。

## ダウンロード(ビルド不要・Release版)

プログラミング環境が無い方は、[Releases](../../releases) から `TSAnalyzeCutMerge.zip` をダウンロードして展開し、中の `TSAnalyzeCutMerge.exe` を実行してください。同梱の「はじめにお読みください.txt」もご確認ください。

**同梱していないもの**(ライセンス上、各自入手が必要です):

- **TsSplitter**: 配布元にライセンス表記が見当たらないため同梱していません。お使いの入手先からダウンロードし、起動後の「詳細オプション」タブでパスを指定してください。
- **ffmpeg**(任意): サムネイル生成にのみ使用します。無くても分割・結合等の主要機能は動作します。

**同梱しているもの**: rplsinfo(作者が再配布を許諾しているため同梱)。

## ソースから使う場合

### 前提環境

- Windows 10/11、Python 3.9以降
- 公式インストーラーでPythonを入れ、**「Add python.exe to PATH」にチェックを入れてインストール**してください。コマンドプロンプトで `py --version` または `python --version` が通ることを確認してください。
- `run_gui.bat` は `py` → `python` の順にPATH上から自動検出します。どちらも見つからない場合はエラーメッセージが出ます。
- Microsoft Store版Pythonや、PATHに登録していない手動インストールの場合は自動検出できないことがあります。その場合は `python main.py` を、Pythonのフルパスを使って直接実行してください(例: `"C:\Python312\python.exe" main.py`)。

### 実行

```bat
run_gui.bat
```

または `python main.py` を実行してください。ドラッグ&ドロップ対応のため `tkinterdnd2` を使用します(`run_gui.bat`が未導入時に自動インストールします。手動なら `pip install tkinterdnd2`)。未導入でもドラッグ&ドロップが無効になるだけで他の機能は通常どおり使えます。

1.「ファイル / 実行」タブで対象の `.ts` / `.m2ts` ファイル(複数可)またはフォルダを追加(「ファイル追加...」「フォルダ追加...」ボタンのほか、**エクスプローラーからファイル/フォルダを直接ドラッグ&ドロップ**しても追加できます)
2. 出力先(既定: 入力ファイルと同じ場所に `元ファイル名_split` フォルダを作成)を確認
3. 必要に応じて「詳細オプション」タブで分割モードや保持データを調整
4. 「分割開始」を押す

処理中はログと進捗(TsSplitterの読み込み%)が表示されます。完了後、出力フォルダに分割後のファイルと `.info.txt`(番組情報)、`split_summary_*.csv`(一覧)が作成されます。

### 詳細解析モード(既定でON): 番組候補をサムネイル付きで確認してから抽出

PEGASYS TMPGEnc MPEG Smart Renderer の「TSファイル追加ウィザード」のように、TsSplitterでのチャンネル/PMT単位の粗い分割の後、各区間をさらに`rplsinfo`で細かくサンプリングして**番組の切り替わり地点を検出**し、サムネイル・番組名・放送局・日時つきのチェックリストを表示します。

- 同一チャンネル・同一PMTのまま番組だけが切り替わる境目も検出できます(簡易モードでは検出できなかったケース)。
- サムネイルは `ffmpeg`(ARIB字幕対応ビルドを実機で確認済み)で生成します。`ffmpeg` が見つからない場合はサムネイル無しで一覧のみ表示されます。
- 一覧でチェックを外した項目は抽出されません(既定は全選択=元データをそのまま保全する方向)。
- **テープ再生中のドロップアウト対策**: 前後が同じ番組と確認できる場合、その間にある瞬間的な情報欠測区間(ドロップアウト等)は分割点とみなさず、前後の番組候補に自動的に統合します。前後で番組情報が異なる場合(実際のチャンネル/番組切替の可能性がある場合)は統合せずそのまま候補として残します。
- 「選択項目を抽出」を押すと、選択された範囲だけをバイト単位でロスレス切り出しし、`rplsinfo`で最終確認のうえリネームします。

「ファイル / 実行」タブの「詳細解析して番組ごとに候補を確認してから抽出する」のチェックを外すと、以前と同じ高速・簡易モード(粗い分割結果をそのまま採用)で動作します。

### 出力フォルダの整理(中間ファイルの片付け)

詳細解析モードでは、番組候補を切り出すために TsSplitter の粗分割ファイル(`元ファイル名_HD-N.m2ts`等)をいったん作成しますが、これらは切り出しが終われば不要になります。既定では出力フォルダの見通しを良くするため、これらの中間ファイルと `.log`/`_tsselect.log` を **`_work` サブフォルダへ自動的に移動**します(削除はしません)。「ファイル / 実行」タブの「出力先」欄で、削除する/そのまま残す への変更も可能です。

また、「実行前に出力先を確認する」を有効にすると、処理開始前に解決済みの出力先一覧をダイアログで確認できます。

### 放送局ごとのグループ表示・結合

1本のテープに複数の録画セッション(別局・別日時)が混在していると、粗い分割だけで多数のファイルに分かれることがあります。候補確認画面では:

- 表示を「放送局ごと」に切り替えると、テープ内のどこにあったかに関わらず同じ局の項目がまとめて表示されます(既定でこの表示)。
- 「同じ放送局の選択項目を時系列順に1つのファイルへ結合する」にチェックを入れると、選択した同一局の項目を元の時系列順にロスレス結合して1本のファイルにまとめます。放送局が不明な項目同士は根拠が無いため結合されず、常に個別のファイルとして保存されます。
- 結合の継ぎ目ではタイムスタンプが不連続になるため、プレーヤーによっては一瞬再生が乱れる場合があります。気になる場合は詳細オプションの`-PTS`や、TSCutter.GUI等のタイムライン修復ツールの利用も検討してください。

### 過渡的な断片の手動グループ分け・結合順の並べ替え・重複データ除去

候補確認画面(放送局ごと表示)では、各項目の右側で以下が行えます:

- **グループ移動**: プルダウンで所属グループ(放送局)を変更できます。情報が取得できなかった「過渡的な断片」も、任意の放送局グループへ手動で入れたり、新しいグループ名を入力して独自のまとめグループを作ったりできます。
- **▲▼ 結合順の入れ替え**: グループ内での結合順(上から下へ結合されます)を手動で並べ替えられます。

結合時には、**同じ放送を複数回ダビングした際にできる重複データを自動検出して除去**します(次のファイルの先頭一定サイズを、既に書き出し済みの末尾側から探して一致すれば、その重複区間を破棄してから結合)。このアルゴリズムは [nilaoda/TSMerge](https://github.com/nilaoda/TSMerge)(MIT License)の設計を参考にPythonで再実装したものです。実データに近い合成テストで、重複区間が正しく検出・除去され、結合後のバイト列が期待どおりになることを確認済みです。

**元ファイルは変更・削除しません。** 出力は常に別ファイルとして作成されます。

## 対応形式

- 拡張子: `.ts`, `.m2ts`
- パケットサイズ: 188バイト / 192バイト(m2ts/BDAV形式)は自動判別・無変換でそのまま処理できます(TsSplitter/rplsinfo共に自動対応することを実機確認済み)。204バイト(FEC付き)を検出した場合は188バイトへ自動変換してから処理します。

## 分割モードについて(重要)

| モード | 動作 | 備考 |
|---|---|---|
| **SEP2(既定・推奨)** | 番組情報(EIT)またはPMTが変化した地点で分割 | チャンネル切替にもEITありの通常番組切替にも対応 |
| SEP3 | PMTが変化した地点でのみ分割 | CM等の細切れが少ない |
| SEP | EIT(番組情報)が変化した地点でのみ分割 | **標準EITが無いパーシャルTSでは分割されません(下記参照)** |
| NONE | 分割せず不要データ削除のみ | HD/SD/1SEGの仕分けだけ行いたい場合 |

### 既知の制約: 同一チャンネル内での番組の切れ目

D-VHS等のパーシャルTSキャプチャには、標準の番組情報(EIT, PID 0x12)が入っておらず、代わりに ARIB のパーシャルTS拡張である **SIT(Selection Information Table, PID 0x1F)** に番組情報相当のデータが格納されています(実機のTS解析により確認)。

- `TsSplitter` の `-SEP`(EIT基準の分割)はこの構成のTSでは分割点を検出できません。実データで検証した結果、`-SEP` 単体では**分割が一切行われませんでした**。
- `-SEP2` / `-SEP3` は PMT の変化を検出して分割しますが、**同じチャンネルのまま番組だけが切り替わり、PMTの構成(映像/音声PID等)が変化しない場合は分割されません。** 実データでも、1つのPMT区間の中に放送日時の異なる複数のNHKスペシャル番組が連続して含まれているケースを確認しています。

つまり本ツールは **チャンネル切替・別放送局・別日付をまたぐデータの自動分割** には強力に対応できますが、**同一チャンネルで途切れなく連続する番組同士の境目** を完全に自動検出することは、現状のTsSplitterの仕組み上できません。

このようなケースでは、詳細オプションの `-TIMECUT` / `-CUT`(時刻/経過時間指定分割)を使い、`.info.txt` や再生ソフトで確認した番組の切り替わり時刻を手動指定して追加で分割してください。

## 重要な実装上の注意

### SIT(PID 0x1F)の保持

`TsSplitter` の `-EIT` オプションは NIT〜TOT(PID 0x10-0x14)は保持しますが、パーシャルTSのSIT(PID 0x1F)は対象外です。これを保持せずに分割すると、分割後のファイルから `rplsinfo` が番組情報を読み取れなくなることを確認したため、本ツールは**常に `-PID1f` を追加してSITを保持**するようにしています。

### dデータ放送等、PMT記載の全PIDを自動検出して保持

`TsSplitter` は既定では映像・音声・PCR・EIT等、自身が認識する既知の種別のPIDしか保持せず、**データ放送(dデータ放送)のデータカルーセル(stream_type 0x0D)等、それ以外のPMT記載PIDは黙って削除**することを実機検証で確認しました(実データで7種類のPID、15万パケット以上が無音無警告で失われていました)。

これに対応するため、本ツールは分割の前に入力ファイルを複数地点でサンプリングし、実際に使われている全PID構成を検出したうえで `-PID` オプションに明示的に指定し、種別を問わずPMT記載の全ストリームを保持するようにしています(詳細オプションの「PMT記載の全PIDを自動検出して保持する」で無効化も可能。無効にした場合、追加PID欄で手動指定したPIDのみが追加保持されます)。

実データで検証し、データカルーセルPID(0x0140, 0x0160-0x0162, 0x0170-0x0172)が分割後・結合後のファイルでも正しく保持されることを確認済みです。

## 番組情報の取得(rplsinfo)について

- `rplsinfo` はファイル内の指定位置(0=先頭 ～ 99=終端、既定50)から番組情報を探索します。分割後の各ファイルに対し、既定では 50→30→70→10→90→0→99 の順に自動的に位置を変えて探索し、最初に成功した結果を採用します。
- ごく短い断片(数十KB程度、チャンネル切替直後の過渡データなど)では、番組情報が見つからないことがあります。その場合もファイルは削除・破棄せず、`情報不明` を含む簡易的な名前で保存されます。

## リネームパターン

`{date} {time} {station} {channel} {title} {orig} {suffix} {ext}` が使えます。既定値:

- 成功時: `{date}_{time}_{station}_{title}_{suffix}`
- 失敗時: `{orig}_{suffix}_情報不明`

## 関連ツールとの役割分担

D-VHSバックアップ特有の以下のようなニーズには、本ツールではなく専用ツールの併用を推奨します(本ツールは「番組情報を読み取って自動的に分割する」ことに特化しており、汎用的なTS修復・編集エンジンではありません)。

- **フレーム精密なカット編集**
- **TSタイムライン修復**(PCR/PTSの不連続を安全に補正)
- **TSマルチソース修復**(同じ放送の複数の録画/ダビング元を比較し、健全な方のデータで欠損・破損区間を補う)
- **TSバイナリマージ**(複数ファイルの結合、重複部分の検出・除去)

これらは [TSCutter.GUI](https://github.com/nilaoda/TSCutter.GUI)(GPL-3.0, Windows/Linux/macOS対応)が専用機能として持っています。本ツールの`-PTS`オプション(タイムライン、詳細オプション内)はTsSplitter由来の簡易的なPTS/PCR振り直し機能で、上記の「タイムライン修復」の簡易版に相当しますが、本格的な多源修復やマージが必要な場合はTSCutter.GUI等をお使いください。

```
TSAnalyzeCutMerge/
  main.py              GUI本体
  run_gui.bat           起動用バッチ(ソース実行用)
  build_release.py       Release配布用exeのビルドスクリプト(下記参照)
  ts_tools/
    probe.py            パケットサイズ判定・204→188変換・バイト範囲抽出
    splitter.py          TsSplitter.exe ラッパー
    rplsinfo.py           rplsinfo.exe ラッパー(位置スイープ対応)
    analyzer.py            サンプリング+二分探索による番組境界検出
    mpegts.py               MPEG-2 TS公開仕様に基づくPAT/PMT解析・キーフレーム検出
    overlap.py               結合時の重複バイナリデータ検出・除去
    thumbnail.py              ffmpegによるサムネイル生成(任意)
    review_ui.py               番組候補チェックリスト画面(詳細解析モード)
    naming.py                   ファイル名生成・サニタイズ
    pipeline.py                   全体の処理フロー(簡易/詳細解析の両モード)
    config.py                      既定パス等の設定
```
